# Tapir

**Tapir — инструмент для автоматизации E2E-тестирования REST API.**
Загрузите Swagger-документацию, получите базовые тестовые сценарии, отредактируйте их и запускайте где удобно: в CLI, Docker или во встроенном локальном веб-интерфейсе.

> Статус: проект в разработке. Ниже описано, как Tapir устроен и что он умеет по плану MVP.

## Зачем это нужно

Чтобы проверить, что API работает и не сломался, разработчик пишет E2E-тесты. Это монотонно, а дальше становится только хуже:

- нужно держать в голове текущее состояние API и уже написанные сценарии;
- при большом числе тестов файл с ними превращается в нечитаемый;
- при изменении ручки все затронутые тесты приходится искать и править вручную;
- в Postman сценарии собираются только руками.

Tapir берёт на себя рутину и оставляет вам контроль над результатом.

## Как это работает

1. **Загрузите Swagger.** В MVP поддерживается Swagger 2.0 (JSON или YAML).
2. **Получите сценарии.** Tapir разберёт ручки и схемы и построит базовые сценарии.
3. **Отредактируйте.** Правьте их в интерактивном конструкторе или прямо в JSON.
4. **Сохраните в git.** Сценарии лежат в одном читаемом JSON-файле рядом с вашим кодом.
5. **Запустите.** CLI, Docker-образ или локальный интерфейс.
6. **Изучите отчёт.** Для каждого шага видно ожидаемый и реальный ответ.

## Возможности

- **Генерация сценариев из спецификации.** Smoke-сценарий на каждую ручку, CRUD-цепочки и простые негативные кейсы (400, 404, 401).
- **Сценарии в git.** Один читаемый JSON-файл: код-ревью, диффы и ручная правка работают как обычно. Секреты в файл не попадают, в нём только ссылки на переменные окружения.
- **Актуальность при изменении API.** Шаги ссылаются на ручки по `operationId`. Если Swagger изменился, Tapir покажет затронутые шаги, а вы решите: обновить или пропустить.
- **Интерактивный конструктор.** Редактирование сценариев, логин-фикстуры, несколько ролей (акторов) для проверки ролевых API, передача данных между шагами.
- **Расхождения со спецификацией.** Если ответ API не совпадает со схемой Swagger, это попадает в отдельный раздел отчёта. Флаг `--strict-schema` превращает такие расхождения в падения теста.
- **Локальный интерфейс.** Команда `tapir ui` поднимает веб-интерфейс в Docker, он видит приватные API и сети docker-compose.
- **Готовность к CI.** CLI не задаёт интерактивных вопросов, возвращает код выхода и сохраняет отчёт в `report.json`.
- **Безопасность.** Токены и пароли маскируются в логах и отчётах.
- **Язык интерфейса.** Английский и русский.

## Как выглядит сценарий

Пример в формате Tapir (черновой, формат может измениться до релиза):

```json
{
  "name": "Petstore E2E",
  "scenarios": [
    {
      "id": "pet-lifecycle",
      "steps": [
        {
          "operation": { "operationId": "addPet" },
          "expect": { "status": 200 }
        },
        {
          "operation": { "operationId": "getPetById" },
          "expect": { "status": 404 }
        }
      ]
    }
  ]
}
```

Планируемый набор команд CLI: `init`, `generate`, `validate`, `run`, `ui`.

## Чего пока нет

В первую версию не войдут: запуск тестов с серверов Tapir, уведомления (Telegram, Slack, email), миграция из Postman, совместная работа в команде, протоколы кроме REST (GraphQL, gRPC и WebSocket планируются позже), OpenAPI 3.x.
